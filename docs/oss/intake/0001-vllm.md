## Why we needed something here

Serving Trida's block-diffusion and self-speculative decoding paths needs an engine
with paged KV cache, CUDA graph capture and continuous batching. Writing that
ourselves is a year of work that is not our research.

## Alternatives considered

| 후보 | 왜 선택하지 않았나 |
|---|---|
| Fork vLLM | a fork is a permanent merge tax, and it hides our changes from anyone reading our repository. The out-of-tree plugin interface gives us the same hooks. |
| TensorRT-LLM | closed build toolchain, and the model contract we need is not expressible without upstream changes |
| Writing our own server | see above |

## Decision

Adopt as an **out-of-tree plugin**, never a fork. The pin is `>=0.27,<0.28`: the
plugin interface is not covered by a stability guarantee across minors, so a minor
bump is a deliberate change with its own PR.

The #60 decision server uses a separate stock **0.32.0** environment and its
worker-extension/RPC API to capture hidden states from one generation runner.
Concurrent serving wraps the V2 runner's `add_requests` and `sample` methods;
`--max-concurrency 1` retains the serial `compute_logits` hook. These internal
hooks must be revalidated on upgrades. It does not load the diffusion plugin or change its
`>=0.27,<0.28` requirement. H100 validation and the remaining limitations are
recorded in `inference/zoro-1/vllm/DECISION_VALIDATION.md`. The original score
above belongs to the diffusion integration assessment; this addition records
the separate decision-serving version, not a new numerical assessment.

The decision server’s Linux/Python 3.12 environment is pinned in
[`requirements-decide-lock.txt`](../../../inference/zoro-1/vllm/requirements-decide-lock.txt)
and included in the advisory scan. The new setuptools advisory
GHSA-xmj3-9gf7-h52w awaits maintainer disposition; vLLM’s <81 constraint prevents
taking the 84.1.0 fix in this validated environment. No new exception is approved.
See the validation notes for the exact scope and scan results.

## Obligations we take on

Apache-2.0 attribution in [`NOTICE`](../../../NOTICE). State changes where we modify
behaviour — we do not modify vLLM sources, which is part of why this layout was
chosen.

## Re-evaluation trigger

Annually, and immediately on any of: the plugin interface changing incompatibly,
the licence changing, or a security finding in the serving path that upstream does
not fix within the window in [`SECURITY.md`](../../../SECURITY.md).
