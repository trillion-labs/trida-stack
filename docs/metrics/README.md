# 응답 지표

기여자 경험을 어떻게 재는지, 그리고 **무엇을 재지 않는지** 적습니다.

이 문서가 공개 저장소에 있는 이유는 하나입니다. 질문을 올리는 사람이 **자기 질문이
어떻게 측정되는지, 그리고 자신이 평가 대상이 아니라는 것**을 알 수 있어야 하기 때문입니다.

## 무엇을 재는가

| 지표 | 정의 |
|---|---|
| 첫 사람 응답시간 | `first_human_response_at − created_at` — 중앙값과 p90, 영업시간 기준 |
| 미응답률 | 사람 응답이 아직 없는 항목의 비율 |
| SLA 달성률 | 기준 시간 안에 응답한 비율 |

**응답은 작성자가 아닌 사람의 댓글 또는 리뷰입니다.** 봇과 작성자 본인의 댓글은 응답이
아닙니다.

**측정 대상은 외부 기여자입니다.** 메인테이너가 열고 메인테이너가 병합한 PR은 방치된
기여가 아니므로 모집단에서 제외합니다. 이걸 섞으면 미응답률 100%처럼 산술적으로는 맞고
의미는 없는 숫자가 나옵니다.

**앞의 두 개는 함께 봅니다.** 아무도 답하지 않은 항목은 응답시간 표본에서 아예
사라지므로, 중앙값이 좋으면서 동시에 방치가 만연할 수 있습니다. 미응답률 없이
응답시간만 읽는 것이 이 조합이 막으려는 실수입니다.

**평균이 아니라 중앙값과 p90입니다.** 평균은 몇 달째 방치된 한 건을 가립니다.

## 내부 계열은 따로 잽니다 — 섞지 않습니다

메인테이너가 연 항목은 위 세 지표의 모집단에서 빠지지만, **버려지지는 않습니다.**
`M-101 첫 사람 응답시간(내부)`로 **별도 계열**에 기록합니다.

| | 묻는 것 |
|---|---|
| M-001~M-003 (외부) | 여기에 기여하는 건 어떤 경험인가 |
| M-101 (내부) | 메인테이너가 얼마나 빨리 응답하는가 |

둘을 합치면 둘 다 망가집니다. 그런데 외부 기여자가 아직 없는 기간에 내부를 버리면
**아무것도 측정되지 않은 것과 구분되지 않는 `null` 줄만 남습니다.** 그래서 따로 둡니다.

**내부 계열에는 미응답률이 없습니다.** 메인테이너가 열고 스스로 머지한 항목은 응답을
기다린 적이 없으므로, 비율로 만들면 방치처럼 읽히는 큰 숫자가 나옵니다. 비율 대신
`closed_without_an_outside_response` **건수**로만 적습니다.

## 측정하고 끝내지 않습니다

기간마다 스냅샷 하나(`metrics/snapshots/<ISO주>.json`)와 검토 기록
하나([`reviews/`](reviews/))를 남깁니다. 검토 기록에는 **무엇을 쟀나 / 무엇을
발견했나 / 무엇을 하기로 했나**를 적습니다. 바뀐 게 없으면 없다고 적습니다.

관찰 기간에는 **주간**, 90일 기준선이 생기고 목표를 정한 뒤에는 월간입니다.

## 아직 목표가 없습니다

저장소는 2026-09-28에 공개됐습니다. 새 프로젝트는 처음 4~8주를 **관찰 기간**으로 두고
목표 대신 데이터 품질을 확인하며, 목표를 정하기 전에 90일 기준선을 봅니다.

그래서 지금 어떤 지표에도 목표가 없습니다. `COMMUNITY.md`의 "영업일 2일 이내 첫 분류"는
**잠정 기준이지 약속이 아닙니다.** 목표를 정할 때는 하나가 아니라 셋으로 정합니다 —
목표 / 경고 / 중단 조건.

## 채팅에서 답하면 지표가 틀립니다

응답 시점을 **GitHub 댓글 타임스탬프**로 재기 때문에, Discord에서만 답하면:

- 10분 만에 도왔어도 → 지표상 **미응답**
- 미응답률이 실제보다 높게 나오고
- SLA는 측정 불가

지표가 틀리는 것보다 큰 문제는 지식이 사라지는 것입니다. 그래서
[`../community/MODERATOR_RUNBOOK.md`](../community/MODERATOR_RUNBOOK.md)의 승격 절차가
예의가 아니라 **운영 의무**입니다. `stale-unanswered.yml`이 안전망으로, 채팅에서만 답한
항목은 누군가 GitHub에 기록할 때까지 평일마다 계속 올라옵니다.

## 개인을 측정하지 않습니다

공개된 GitHub 데이터라도 무제한 프로파일링 허가가 아닙니다.

**하지 않는 것:** 개인별 응답 순위, 야간·주말 활동 추적, 감정 추정, 국가·성별 추론.

집계는 프로젝트 단위로만 합니다. 메인테이너가 3명뿐이라 개인별 지표는 사실상 특정
개인을 지목하는 것과 같습니다. 그것은 더 많이 수집할 이유가 아니라 **조심할 이유**입니다.

## 한계

- 영업시간은 주말을 제외하지만 **공휴일은 제외하지 않습니다**
- 봇은 계정 유형과 `[bot]` 접미사로 거릅니다. 자동화에 쓰이는 사람 계정은 못 거릅니다
- **빠른 형식적 응답이 해결을 뜻하지 않습니다.** 응답시간이 좋아도 문제가 안 풀렸을 수 있습니다
- 외부/내부 구분은 협업자 목록을 쓰므로, 나중에 쓰기 권한을 받은 기여자는 기간 사이에 모집단이 바뀝니다
- 현재 **GitHub만** 봅니다. Hugging Face Discussion으로 들어온 문의는 잡히지 않습니다
- 스냅샷은 저장소 전체 이력에 대한 **누적값**입니다. 기간별 증분이 아닙니다
