# Chat channel policy

채팅 채널(Discord 또는 Slack)의 운영 규칙입니다. 채널 개설 전에 확정하고, 서버의
읽기 전용 `#rules` 채널에 그대로 게시합니다.

## 목적과 기록 원칙

채팅은 **빠른 대화와 관계 형성**을 위한 공간입니다. 릴리스 결정, 재현 가능한 버그,
기능 요구, 장기적으로 재사용할 답변은 **GitHub 또는 해당 Hugging Face 저장소에
기록합니다.**

**공식 결정은 채팅 메시지만으로 확정하지 않습니다.** `#general`에서 기술 결정을
확정하지 않고, 결정은 기준 시스템에 근거와 함께 남깁니다.

## 허용되는 사용

- 프로젝트 사용법 질문과 상호 도움
- 공개된 로드맵·기여 작업 논의
- 행사와 릴리스 안내

## 금지되는 사용

- 차별, 괴롭힘, 위협, 신상 공개
- 스팸, 무단 홍보, 반복적인 사적 메시지
- **토큰·암호·개인정보·미공개 취약점 게시**
- 지원 담당자에게 답변을 강요하거나, 같은 질문을 여러 채널에 반복 게시

플랫폼 자체의 커뮤니티 규칙이 함께 적용되며, **플랫폼 규칙보다 완화된 서버 규칙을
만들 수 없습니다.**

## 최소 채널 구조

처음에는 적은 채널이 낫습니다. 활동이 분산되면 빈 방이 늘고 질문이 보이지 않습니다.

```
START-HERE
  #rules            읽기 전용 — 규칙과 신고 경로
  #announcements    읽기 전용 — 릴리스·보안 공지
PROJECT
  #general          일반 대화 (기술 결정 확정 금지)
  #help             짧은 사용 질문 — 질문마다 thread로 분리
  #contributors     이슈·PR·개발환경 협의
PRIVATE
  #moderators       당번·운영 협의 (사건 논의는 여기가 아님)
```

**보안 신고와 민감한 모더레이션 사건을 비공개 채널 하나에 쌓지 않습니다.** 전용 신고
경로를 쓰고, 채팅에는 **사건 ID와 필요한 최소 정보만** 둡니다.

새 채널은 목적·예상 참여자·책임 운영자·GitHub 연결점·60일 검토일이 있을 때 만듭니다.
30일간 유효 대화가 거의 없으면 상위 채널로 합치고 읽기 전용 안내를 남긴 뒤 보관합니다.

## 역할과 최소 권한

| 역할 | 책임 | 필요한 권한 |
|---|---|---|
| 커뮤니티 리드 | 목표, 당번, 월간 리뷰, 대외 공지 | 설정 변경 승인 |
| 메인테이너 | 기술 답변, 작업 승인, 릴리스 연결 | GitHub write/maintain |
| 트리아저 | 질문 분류, 중복 연결, 라벨 | GitHub triage |
| 모더레이터 | 규칙 안내, 신고 접수, 긴급 제한 | 메시지 관리·제한 |
| 보안 담당 | 취약점 비공개 접수와 대응 | 보안함 최소 접근 |

**모더레이터에게 서버 소유자나 모든 GitHub 관리 권한을 주지 않습니다.** 봇도 읽기·쓰기
범위를 최소화하고, 토큰을 저장소에 커밋하지 않습니다. 소유권은 개인 계정 하나에
의존하지 않고 승계 절차와 비상 연락망을 둡니다. 관리자와 운영자는 다중요소 인증을
사용합니다.

> **담당자 미지정.** 가이드는 커뮤니티 리드·기술 당번·모더레이터·보안 담당을 실명으로
> 지정하도록 요구합니다. 아직 배정되지 않았습니다 — 채널 개설 전에 채웁니다.
