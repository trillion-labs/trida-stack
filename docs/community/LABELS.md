# Labels

가이드 §2.3은 라벨의 **뜻과 종료 기준이 일치**해야 한다고 요구합니다. 라벨이 무엇을
의미하는지와 **언제 떼는지**를 함께 적습니다.

| 라벨 | 뜻 | 종료 기준 |
|---|---|---|
| `triage` | 분류 대기 — 담당자와 기준 채널이 아직 정해지지 않음 | 담당자가 정해지고 유형이 확정되면 뗀다 |
| `community` | 채팅 또는 Discussion에서 전환된 항목 | 떼지 않는다 — 출처 표시 |
| `good first issue` | 배경·파일 위치·예상 변경 크기·검증 방법·질문할 곳이 **본문에 적혀 있는** 작업 | 병합되면 닫힌다 |
| `help wanted` | 메인테이너가 당장 잡지 않으며 외부 기여를 환영하는 작업 | 담당자가 생기면 뗀다 |
| `question` | 결함이 아니라 사용 질문 — Discussions로 옮기는 것을 우선 검토 | 답변 후 닫거나 Discussion으로 전환 |
| `bug` | 재현 절차가 확인된 결함 | 수정이 릴리스되면 닫는다 |
| `documentation` | 문서만 바뀌는 작업 | 병합되면 닫힌다 |
| `enhancement` | 범위가 합의된 기능 작업 | 병합되면 닫힌다 |
| `duplicate` / `invalid` / `wontfix` | 닫는 사유 | 즉시 닫되 **사유를 한 줄 남긴다** |

`good first issue`는 수가 아니라 품질입니다. 배경, 파일 위치, 예상 변경 크기, 검증
방법, 막혔을 때 질문할 곳이 본문에 없으면 그 라벨을 붙이지 않습니다 — 첫 기여자가
그 다섯 가지 없이 시작할 수 없기 때문입니다.
