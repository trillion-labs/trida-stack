만들지 않는다"* 이고, 이 폴더가 그 첫 주에 해당합니다.

| 문서 | 내용 |

| [`CHANNEL_POLICY.md`](CHANNEL_POLICY.md) | 채팅 채널 규칙·최소 채널 구조·역할과 권한 |
| [`MODERATOR_RUNBOOK.md`](MODERATOR_RUNBOOK.md) | 신고 접수, S1~S4 등급, 사건 기록, 승격 절차 |
| [`LABELS.md`](LABELS.md) | 라벨의 뜻과 종료 기준 |

## 개설 전 체크리스트

가이드 §5.1의 6가지입니다.

- [ ] 주 참여자 **세 유형**과 그들이 해결할 일을 한 문장씩 쓴다
- [x] GitHub·Discussion·채팅·보안 신고의 **채널 맵** 확정 → `CHANNEL_MATRIX.md`
- [ ] 커뮤니티 리드 / 기술 당번 / 모더레이터 / 보안 담당을 **지정**
- [x] 목표 응답시간과 운영 시간대 → `COMMUNITY.md` (영업일 2일, 평일 09–18 KST)
- [x] COMMUNITY.md·행동강령·채널 정책 **초안 리뷰**
- [ ] 월간 지표와 개인정보 최소 수집 원칙 → [`../metrics/README.md`](../metrics/README.md)

## 출범 보류 조건 — 하나라도 해당되면 공개 초대를 열지 않습니다

가이드 §5.1이 정한 조건이고, 문서가 준비된 것과 운영이 가능한 것은 다릅니다.

- [ ] **비공개 신고가 실제로 수신되는가** — `security@trillionlabs.co`,
      `conduct@trillionlabs.co` 로 테스트 메일을 보내 각각 **2명 이상**이 받는지 확인.
      **아직 미확인.** CI는 주소가 적혀 있는지만 보며, 메일이 도착하는지는 볼 수 없습니다.
- [ ] **관리자 계정 복구가 되는가** — 소유 계정 복구 경로, 관리자 2인, MFA
- [ ] **휴가 때 대신할 운영자가 있는가** — 1인 의존이면 열지 않는다

## 이 단계에서 안 하는 것

- **빈 커뮤니티를 공개하지 않습니다** (§5.3). 먼저 FAQ 10개를 Discussions Q&A에
  올리고 답변 표시, 실제로 처리 가능한 `good first issue` 3~5개를 준비합니다.
- **전체 공개로 시작하지 않습니다** (§5.4). 기존 사용자와 협력기관 등 작은 그룹에
  먼저 열고, 신규 참여자가 안내만 보고 올바른 곳에 질문하는지 관찰합니다.
- 메일링리스트와 별도 포럼은 범위 밖입니다.

## 운영 루프

- **매일/당번일** — 새 질문 환영, 스팸·안전 신고 확인, 답이 필요한 항목에 상태 표시
- **매주 30분** — 미응답 질문, 오래된 스레드, 승격할 지식, 막힌 첫 기여 이슈, 다음 공지
- **매월** — 지표와 운영 부하, 반복 질문, 사건 추세, 채널 활성도.
  FAQ로 제거할 질문을 고르고, 사용하지 않는 채널과 과도한 봇 권한을 정리
- **분기** — 정책·연락처·초대 링크·운영자 권한 재검증

`stale-unanswered.yml` 이 평일 아침마다 48시간 이상 응답 없는 항목을 채팅으로 보냅니다.
웹훅 시크릿(`DISCORD_WEBHOOK_URL` 또는 `SLACK_WEBHOOK_URL`)이 설정되면 동작하고,
없으면 로그에 출력만 하고 실패하지 않습니다.
